# Netlane для Windows

Лёгкий portable-клиент для Windows 10/11 x64: .NET Framework 4.8, движок TrustTunnel и Wintun. Это самостоятельная оболочка проекта, не официальный GUI TrustTunnel.

## Установка

1. Скачайте `Netlane-windows-x64.zip` и `.sha256` из [Releases](https://github.com/divezh/netlane-windows/releases/latest).
2. Сравните SHA256 и распакуйте **весь** ZIP. Запускайте `Netlane.exe` рядом с `engine/` и `licenses/`.
3. Приложение открывается с обычными правами; при подключении появляется запрос UAC. Smart App Control может блокировать неизвестные приложения; подпись доверенным сертификатом повышает совместимость. Подробнее — в [README](../../README.md).

```powershell
Get-FileHash .\Netlane-windows-x64.zip -Algorithm SHA256
Get-Content .\Netlane-windows-x64.zip.sha256
```

В архиве находятся EXE, его `.config`, движок и лицензии. README, QA и тестовые программы в пользовательский архив не включаются. Отдельный EXE без `engine/` не работает.

## Подключение

В панели администратор создаёт пользователя, применяет доступ и выдаёт ссылку подписки. Нажмите **«Вставить»** на главном экране клиента. Также поддерживаются отдельные ссылки `tt://` и TOML-профили из панели.

Подписки обновляются при запуске, включая запуск в трей, и при повторном открытии из трея. Ручное обновление — щелчок по строке аккаунта внизу навигации или кнопка «Обновить» на странице «Серверы». Автоподключение ждёт попытку обновления; ошибка сети сохраняет прежние серверы. Импорт подписки сам по себе VPN не включает.

Нажмите «Подключиться» и подтвердите UAC. «Подключено» означает подтверждённое соединение движка. Смена сервера при активном VPN вызывает переподключение. Выход из приложения штатно отключает VPN.

## Транспорт и защита

- **HTTP/2 / TCP** — начальный вариант, обычно подходит для большинства сетей.
- **HTTP/3 / QUIC / UDP** — альтернативный транспорт; требует доступного UDP 443.
- **Anti-DPI** — дополнительные меры клиента против распознавания соединения. Включайте при обрывах/блокировках; результат зависит от сети.
- **Kill Switch** — блокирует обычный доступ при неожиданном обрыве VPN; штатное отключение снимает блокировку.

Проверка ping показывает достижимость выбранного сервера. Скорость, срок доступа и квоту контролирует сервер.

## Правила и DNS

На странице «Подключение» в поле «Набор правил» выбирается весь трафик или набор правил доменов, IP/подсетей и приложений. Правила приложений требуют комплектного движка с поддержкой маршрутизации приложений.

Наборы и DNS администратора приходят через подписку и редактируются в панели. Для личных изменений можно создать копию набора. Обновлённые правила и DNS применяются при следующем подключении.

Личные DNS задаются на странице «Настройки», по одному адресу на строку. Поддерживаются IP, адрес с портом и форматы `tls://`, `https://`, `tcp://`, `quic://`; пустой список использует DNS движка. DNS подписки при включённом управлении имеют приоритет для её серверов. В режиме правил они используются для запросов, направленных через VPN.

Настройки, подписки и личные правила хранятся в `%LOCALAPPDATA%\Netlane\state.bin`, защищённом Windows DPAPI. `.netlanerules` — формат импорта/экспорта правил. Не переносите рабочий `state.bin` другим пользователям.

## Совместимость с другими VPN

Клиент умеет подключаться и тогда, когда другой VPN (L2TP, WireGuard и подобные) забирает маршрут по умолчанию: движок привязывает исходящий сокет к физическому адаптеру, поэтому при подключении клиент сам ставит временный маршрут `/32` до своего сервера через физический шлюз и снимает его при отключении. Увидеть это можно в журнале движка строкой `route: <адрес> via <шлюз> on <адаптер>`. Если другого VPN нет, маршрут не добавляется и ничего не меняется.

Но подключение — это ещё не работа. **Раздельная маршрутизация при поднятом другом VPN не работает**: в режиме «Только указанные адреса через VPN» движок забирает в туннель всю таблицу маршрутов IPv4 и должен сам выпускать остальной трафик, а этот выпуск при чужом маршруте по умолчанию не срабатывает — трафик входит в туннель и не выходит. Проверено на официальном и на собственном движке, с исправленной метрикой адаптера и без неё.

Что работает на практике:

- **другой VPN выключен** — раздельная маршрутизация работает, это рекомендуемый режим;
- **другой VPN включён** — работает режим «Весь трафик» (весь трафик идёт через туннель, прямой выпуск не нужен), но тогда другой VPN для обычного трафика не используется.

## Сборка и проверка

[QA-сценарии](QA.md).

`build-routed-engine.ps1` собирает закреплённый движок с патчами. `build.ps1` компилирует клиент, выполняет встроенные тесты и создаёт ZIP с проверкой хешей движка. Сборки выполняются локально; Actions запускаются только вручную.

Ключ `build.ps1 -Sign` подписывает наши исполняемые файлы сертификатом для подписи кода. Smart App Control может заблокировать неизвестную сборку; для распространения нужна проверка подписи на чистой Windows. Порядок шагов выбран намеренно: подпись идёт до встроенных тестов и до упаковки в ZIP, поэтому в архиве лежит уже подписанный `Netlane.exe`. Подробности и выбор сертификата — в [README репозитория](../../README.md).

Системные маршруты, UAC, Kill Switch, сон/пробуждение дополнительно проверяются на Windows VM. Тесты разбора профилей или SOCKS не заменяют TUN-проверку.

Лицензии движка, Wintun и [flag-icons](https://github.com/lipis/flag-icons) сохраняются в каталоге `licenses/` пользовательского комплекта. Закреплённые версии и проверки находятся в скриптах сборки.
