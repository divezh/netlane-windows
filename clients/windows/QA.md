# Проверка Windows-клиента

## Проверено локально

На Windows x64, .NET Framework 4.8:

- Оболочка компилируется встроенным C#-компилятором без NuGet.
- Тесты импорта TOML панели и `tt://` v1, длинных varint, повреждённых полей и обязательной проверки TLS проходят.
- Файл правил: экспорт и импорт без потерь, отказ чужого JSON, неизвестной версии и отсутствующих правил; в файле нет пароля и имени сервера.
- Правила по имени процесса (Clash `PROCESS-NAME`): валидация имён, отказ пути/искажений и дубликатов, вывод `process_name` в конфиг, сквозной импорт/экспорт через файл правил.
- Переподключение: пауза и номер попытки берутся из строки `Waiting recovery: to next=<ms>` движка и показываются обратным отсчётом.
- Проверены DPAPI CurrentUser, атомарная замена профиля, отказ повреждённого хранилища и закреплённые хеши CLI/Wintun.
- Проверены валидация маршрутов, отказ IPv6-правил при выключенном IPv6, дубликаты путей приложений и генерация конфигурации.
- С официальным движком v1.1.11 выполнены реальные подключения к нашему серверу через HTTP/2 и HTTP/3 с Anti-DPI: TLS с проверкой сертификата, HTTPS 200 через SOCKS, запись серверного расхода, штатная остановка. Временный QA-пользователь удалён. Системные маршруты и DNS хоста не менялись.
- Встроенная проверка до тестового сервера вернула `Ping: 22 мс` (ICMP, медиана трёх ответов). Это измерение с машины разработки по её текущему сетевому маршруту, не обещание такой задержки другим пользователям.
- Реальное подключение через TUN проверено на этой машине: VPN-адаптер с адресом 172.16.219.2, внешние адреса идут через туннель, публичный IP меняется на адрес сервера, DNS-серверы выдаются сервером, адрес самого VPN-сервера и шлюз локальной сети остаются прямыми.

## Маршруты по умолчанию

Официальный CLI v1.1.11 **не подставляет значения по умолчанию** для `included_routes` и `excluded_routes`: если ключей нет в TOML, списки остаются пустыми и движок не добавляет ни одного маршрута. Внешне это выглядит как «Подключено», но трафик идёт мимо туннеля и публичный IP не меняется. Поэтому оболочка всегда пишет оба ключа явно: `included_routes = ["0.0.0.0/0"]` и стандартный список исключений. Удалять их из генерируемого конфига нельзя.

Тот же вывод подтверждает необходимость проверки в интерфейсе: после подключения приложение сверяет, что маршрут по умолчанию идёт через адаптер VPN, и иначе предупреждает вместо ложного «Подключено». Вывод движка пишется в `%LOCALAPPDATA%\Netlane\engine.log` без пароля.

## Проверка интерфейса

Главный экран, настройки и маршрутизация просмотрены с демонстрационным профилем. Основной экран содержит крупную кнопку, карточку сервера и задержку; второстепенные действия вынесены отдельно. Segoe UI, тёмные нейтральные поверхности, голубой акцент, читаемые неактивные элементы, видимые состояния фокуса и выбора. Переключатели и меню рисуются в тёмной теме. Нет фоновых анимаций и встроенного браузера.

Нативная тёмная рамка проверена в открытом окне. `DrawToBitmap` может захватывать светлую системную рамку; это ограничение способа создания превью. Требуется дополнительный проход на Windows 10 и 11 с масштабом 125–200%, клавиатурой и экранным диктором.

## Расширенный движок

Полная сборка должна пройти Windows CI: применение патча к закреплённому исходнику, `make all`, `make test`, `make lint`, затем сборку и тесты оболочки. Наличие патча или успешная сборка оболочки сами по себе не подтверждают работоспособность маршрутизации приложений.

Нативные тесты проверяют политику маршрутов, полный путь и Unicode, неверные и повторяющиеся правила, определение настоящего TCP/UDP-владельца локального соединения и удержание уже установленной Kill Switch-сессии до явного отключения.

## Обязательная проверка на изолированной VM перед стабильным релизом

| Сценарий | Что проверить |
| --- | --- |
| Чистые Windows 10/11 x64 | Распаковка, импорт, UAC, подключение, отключение, восстановление DNS/маршрутов |
| Оба транспорта | HTTP/2 TCP и HTTP/3 QUIC, заблокированный UDP, недоступный сервер |
| Домены и IPv4 | Оба режима, CIDR, wildcard, повторные DNS-запросы и ранее открытые соединения |
| Приложения | VPN/direct, приоритет над адресами, дочерние EXE, одинаковые имена в разных каталогах, неизвестный владелец |
| IPv4/IPv6/DNS | Внешний IP, отсутствие IPv6-обхода, системный DNS и общий DNS-сервис Windows |
| Kill Switch | Обрыв сети после подключения, переподключение, фатальная ошибка, явное отключение, отсутствие прямого трафика |
| Аварийные ситуации | Закрытие GUI/канала, падение CLI, перезагрузка/сон, восстановление сети и временные конфиги |
| Удалённый доступ | Истёкший срок, квота, отзыв пользователя сервером |

Эти системные сценарии пока не подтверждены. SOCKS-проверки их не заменяют. При падении самого CLI или ОС удержание фильтров не гарантируется. Текущая сборка предназначена для тестирования, не считается стабильным релизом.

## Серверы и наборы правил (0.3.0)

Перед выпуском на Windows 10 и 11:

- [ ] Миграция с 0.2.x: профиль с правилами становится сервером и набором «Мои правила», Kill Switch и Anti-DPI сохраняются, `profile.bin` переименован в `profile.bin.migrated`; повреждённый `profile.bin` не трогается, приложение стартует пустым с сообщением.
- [ ] Импорт второго сервера не удаляет первый; повторный импорт того же пользователя спрашивает «Обновить / Добавить копию»; название и флаг из ссылки панели видны в карточке, меню серверов и «Серверах».
- [ ] Переключение сервера и набора при включённом VPN: одно переподключение, статус «Переключаю на «X»…»; **окно без VPN измерено** (секундомер или `ping -t` до внешнего адреса) — цель ≤ 3 с; с Kill Switch подсказка о 1–3 с видна.
- [ ] Сохранение используемого набора при включённом VPN применяет правила переподключением; удаление используемого набора переключает на «Весь трафик».
- [ ] Трей: меню отражает подключение, выбранный сервер и набор; переключение из трея при скрытом окне даёт уведомление «Подключено: X»; обрыв сети — «Соединение потеряно, переподключаюсь»; Kill Switch — своё уведомление; при видимом окне уведомлений нет.
- [ ] Крестик с «Закрытие окна сворачивает в трей» прячет окно (первый раз — уведомление «работает в трее»); без него крестик отключает VPN и закрывает приложение; выключение Windows закрывает приложение без вопросов.
- [ ] «Запускать вместе с Windows»: после выхода и входа в Windows приложение в трее без окна; с «Подключаться к последнему серверу при запуске» VPN включается сам; выключение опции удаляет значение из `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
- [ ] Перетаскивание: `.toml` на главное окно и на «Серверы» добавляет сервер; `.netlanerules`/`.wttrules` на любое окно создаёт набор с именем файла, повтор — «(2)».
- [ ] Масштаб 100 %, 125 %, 150 %, 200 %: главное окно, «Настройки» на всех вкладках, меню серверов и трея — ничего не обрезано; «Сохранить» редактора правил в правом нижнем углу при любом размере окна, растягивание не оставляет артефактов; флаги чёткие (20×15 до 18 px, 40×30 выше).

## Визуальная проверка нового дизайна

Снимки делаются командой `Netlane.exe --render out.png [--state=...] [--page=...]`, окно настроек — `--render-settings out.png [--page=servers|rules|connection|about]` (страница правил — также `--render-routing out.png`), окно в работе — `--preview` / `--preview-settings` с теми же параметрами. Состояния: `noprofile`, `idle`, `connecting`, `connected`, `reconnecting`, `killswitch`, `error`; страницы главного окна: `home`, `import`, `no-servers`, `many-sets`, `servers-menu` (`settings` открывает «Подключение»); длинное имя сервера — `--host=...`.

Перед выпуском на Windows 10 и 11:

- [ ] Все семь состояний главного окна, все страницы навигации и импорт на масштабе 100%, 125%, 150% и 200%: ничего не обрезано и не перекрыто, обе колонки «Подключения» видны при минимальном размере окна 860 × 520.
- [ ] `--state=connected --host=` с именем из 60 символов: имя обрезано многоточием и не заходит на плашку ping.
- [ ] Клавиатура: Tab обходит все элементы, Space и Enter нажимают кнопку подключения, пункты навигации и кнопки, стрелки ходят по таблице локаций (Enter выбирает), переключают транспорт и вкладки маршрутизации; фокус виден бирюзовой обводкой.
- [ ] Настоящее подключение в режиме TUN: блок «Сессия» показывает время и растущий трафик при загрузке; после переподключения значения не уменьшаются и не становятся отрицательными.
- [ ] Страница «Правила» (`--render-routing`) на 200%: строки, вкладки и кнопки масштабируются вместе со шрифтом, ничего не обрезано.
- [ ] Список правил: выделенная строка не темнеет и не «накапливает» цвет при переходах фокуса, рамка фокуса исчезает при уходе из списка.
- [ ] Kill Switch и переподключение показывают красный и жёлтый заголовок состояния; «Удалить…» выбранного сервера красное и доступно только при отключённом VPN.

Проверено под Mono (Linux, Xvfb) снимками всех состояний и экранов: раскладка, цвета, обрезка длинного имени. Полужирный Segoe UI, тёмная рамка окна и масштабы Windows под Mono не проверяются.



## Свой DNS — локальные проверки

Проверены IP/порт и IPv6 в скобках, DoT/DoH/DoQ/TCP-форматы, отказ неправильных адресов и портов, дубликатов, лишних строк и управляющих символов; передача списка в endpoint-конфигурацию; копирование в профиль сеанса; DPAPI-сохранение; редактор, возврат к стандартному DNS, сохранение при работающем туннеле и сохранение прежнего значения при ошибке записи. Сетевое качество и доступность произвольного пользовательского DNS этим тестом не измеряются.

## Подписка (0.4.0) — локальные проверки

Mono и локальная сборка Windows: разбор ответа подписки (версия, `update_hours`, повторяющиеся id, битая ссылка у одной локации отклоняет весь ответ), слияние по id ноды (добавление, обновление пароля, удаление, сохранение подключённого сервера до отключения), пустой список, удаление подписки, сохранение в state.bin; вставка ссылки подписки, повторная вставка, ошибка загрузки без потери списка, одно переподключение при смене пароля подключённого сервера, блок подписки в «Настройки → Серверы», запрет переименования серверов подписки, отказ от ответа больше 256 КБ. Проверка с настоящей подпиской main + нода — на VM с панелью 0.4.0.
