# Установщик Windows

Установщик Inno Setup устанавливает полный комплект в
`%LOCALAPPDATA%\Programs\Netlane`, добавляет ярлык в меню «Пуск» и запись удаления
в настройках Windows. Ярлык рабочего стола необязателен. Установка выполняется
для текущего пользователя; UAC появляется при подключении VPN, как в portable-версии.
Путь доступен встроенному обновлению без повышения прав.

Настройки и подписки остаются в `%LOCALAPPDATA%\Netlane`. Установка, обновление
и удаление их не стирают. Не запускайте мастер от имени другой учётной записи:
данные DPAPI принадлежат исходному пользователю. Перед установкой или удалением
отключите VPN и завершите Netlane через трей, включая другие portable-копии.

## Сборка

Нужен Inno Setup 6.7 или новее из [официального источника](https://jrsoftware.org/isdl.php).
Сначала соберите и проверьте клиент штатным `clients/windows/build.ps1`, затем:

```powershell
powershell -ExecutionPolicy Bypass -File clients/windows/build-installer.ps1
```

Можно упаковать уже проверенный распакованный релиз, не пересобирая движок:

```powershell
./clients/windows/build-installer.ps1 `
    -SourceDirectory C:\build\Netlane `
    -IsccPath 'C:\tools\Inno Setup 6\ISCC.exe'
```

Результат — `artifacts/Netlane-Setup-X.Y.Z-x64.exe` и его `.sha256`. Версия берётся
из самого `Netlane.exe`. В комплект попадают только программа, конфигурация
приложения, движок, Wintun и лицензии; тесты и пользовательские профили исключены.
Файлы payload не модифицируются, поэтому закреплённые хеши движка сохраняются.

Нужен .NET Framework 4.8 или новее. Если его нет, мастер показывает ссылку
Microsoft и прекращает установку; среда выполнения автоматически не скачивается.
Silent-режим: `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`; приложение после него
не запускается. Повторный запуск мастера обновляет ту же установку.

Установщик сам по себе не исправляет ошибку чтения `session.toml` в движке:
это отдельная ошибка клиента, и временная папка Windows здесь не меняется.

## Подпись и выпуск

Локальная сборка мастера не подписана Authenticode. Подпись владельца ZIP
не подписывает EXE установщика. Перед публичным выпуском подпишите финальный
установщик, затем пересчитайте его SHA-256; для цепочки доверия релизов также
выпустите отдельную подпись `.exe.sig` тем же порядком, что и для ZIP.
Portable ZIP остаётся форматом встроенных обновлений.

Финальная подготовка релиза (ключ остаётся локальным и не попадает в комплект):

```powershell
./clients/windows/prepare-release.ps1 -SigningKey C:\private\netlane-release.key
```

Скрипт проверяет версии клиента в ZIP и установщике, подписывает оба файла,
проверяет подписи закреплённым открытым ключом и собирает шесть файлов в `dist/`.
Загрузите все шесть в черновик до публикации неизменяемого релиза.

`publish-local-release.ps1` повторяет полный прогон тестов перед публикацией.
Только для тестового процесса он задаёт отдельную временную папку в
`.tools/release-tests/`; системные TEMP/TMP и права Windows не меняются.
Локальные HTTP-тесты могут требовать PowerShell с правами администратора.
При ошибке проверки публикация прекращается, файлы тестов сохраняются.

## Проверка на тестовой Windows

1. Чистая установка: полный комплект, ярлык «Пуск», запись удаления и запуск.
2. Повторная установка: тот же путь, сохранённые подписки и правила.
3. Подключение/отключение VPN и обновление ZIP из установленной копии.
4. Удаление: файлы программы и ярлыки удалены; настройки сохранены. Запись
   автозапуска удаляется только если ссылается на эту установленную копию.
5. Учётная запись с кириллицей, Windows 10/11 x64 и отказ при отсутствии .NET 4.8.
